# P05 Baseline Gate Amendment: Oracle Timestamp Rounding V3

## Approval and scope

The user approved this amendment on 2026-08-25 with the exact token
`APPROVE_P05_V3_PROTOCOL_REVISION`. It replaces only the P05 V2 engineering
gate. P08 remains unchanged.

## Preserved V2 evidence

Study `ovorb2_p05_baseline_noninferiority_v2` completed all 180 registered
statistical runs and six access audits. Its independent verifier stopped before
statistics because every historical-oracle run serializes TUM timestamps with
insufficient decimal precision for exact floating-point equality. Across all
six sequences, the maximum observed absolute serialization difference was
`5.00679016113e-06` seconds. Candidate telemetry matched association timestamps
exactly. V2 artifacts remain immutable and must not be reported as a completed
statistical result.

## Replacement gate

The replacement study ID is `ovorb2_p05_baseline_noninferiority_v3`. Every V2
design choice remains frozen, including:

- six sequences and repetition IDs 23011 through 23025;
- 15 paired blocks per sequence and 180 statistical runs;
- exact within-block execution order generated by `random.Random(23010)`;
- oracle commit `58014b7c1f2b73427b67b4e80a8cf334127f48ea` and candidate
  `HEAD_AT_REGISTRATION`;
- 100,000 paired PCG64(23010) bootstrap resamples per sequence with shared
  indices and linear quantiles;
- pose lower bound `-0.10` and geometric ATE-ratio upper bound `1.25`;
- six candidate-baseline access audits and every identity/artifact/semantic
  hard gate.

The sole method change is that historical oracle telemetry timestamps are
accepted when their absolute difference from the corresponding frozen
association timestamp is at most `1e-5` seconds. Frame count, frame index,
row order, finite values, and strictly increasing association timestamps remain
mandatory. Candidate telemetry retains exact timestamp equality.

The `1e-5` bound is fixed before V3 registration, exceeds the observed legacy
serialization ceiling by less than a factor of two, and is 2,000 times smaller
than the frozen `0.02` second trajectory-association gate. It is not used for
trajectory association or metric calculation.

## Failure and rerun policy

V3 uses a new immutable registration and fresh 180-run matrix. V2 statistical
runs are not imported, selected, or pooled. Missing or externally interrupted
V3 attempts may be retried only for the same frozen condition; duplicate valid
attempts fail closed. A deterministic or statistical failure blocks semantic
smoke and P05 closure.

logs, caches, datasets, builds, binaries, environments, Agent Pack state, and
